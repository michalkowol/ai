Cursor pagination for orders API

Replace offset pagination in GET /orders with cursor pagination so deep pages stay fast.

Open questions

What should the cursor encode?

The cursor is returned in the response and sent back as after.

Clients cannot depend on the format, so it can change later. Simpler to debug, but becomes a public contract.

Should the cursor be signed?

The cursor only narrows a query the caller is already allowed to run. Prevents tampering, needs key rotation.

Which clients get migrated in this change?

Prompt

Context

Offset queries on the orders table get slow past page 200. Clients only move forward through the list.

Facts

  • orders.id is a monotonically increasing bigint. db/migrations/V1__orders.sql
  • Two internal clients call GET /orders?page=. access logs, last 30 days

Out of scope

  • Backward pagination
