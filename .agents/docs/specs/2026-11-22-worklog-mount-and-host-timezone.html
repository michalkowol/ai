Worklog mount and host time zone in the ai container

The ai launcher mounts ~/.ai/worklog from the host and passes the host time zone, so the agent in the container writes the worklog in local time.

Context

Claude Code runs in the michalkowol/ai container and only sees /workspace and the directories the ai launcher mounts explicitly. The worklog kept by the agent lives on the host in ~/.ai/worklog (D43), and its entries must use local time. The launcher patch comes from decisions D44 and D45.

 # Bind-mounting a missing directory makes Docker create it owned by root on Linux hosts
 mkdir -p "$HOME/.npm"
+mkdir -p "$HOME/.ai/worklog"
+
+# The image has no tzdata, so pass the POSIX rule (last line of the TZif file), e.g. CET-1CEST,M3.5.0,M10.5.0/3.
+TZ_ENV=()
+HOST_TZ="$(tail -n 1 /etc/localtime 2>/dev/null | LC_ALL=C tr -d '\0' || true)"
+if [[ "$HOST_TZ" =~ ^[A-Za-z\<\>+0-9:,./-]{3,64}$ ]]; then
+    TZ_ENV+=(-e "TZ=$HOST_TZ")
+fi

 "${HERDR_HINT[@]}" docker run -it --rm \
@@
     -v "$HOME/.npm:/home/ubuntu/.npm" \
+    -v "$HOME/.ai/worklog:/home/ubuntu/.ai/worklog" \
+    "${TZ_ENV[@]}" \
     "${GIT_ENV[@]}" \

Check inside the container: date shows local time, and ls ~/.ai/worklog works.

Facts

Launcher and image

  • Decisions D43, D44 and D45 come from a spec outside this repo. They are only quoted here. user prompt
  • The launcher already creates ~/.npm before docker run, because Docker creates a missing directory as root. ai, comment before mkdir -p "$HOME/.npm"
  • The same docker run serves --claude, --cursor and --bash, so the mount and TZ reach all three. The dashboard container has its own docker run. ai
  • The mount maps $HOME/.ai/worklog to /home/ubuntu/.ai/worklog: the same path relative to the home directory, but not the same absolute path on macOS (/Users/…). patch
  • ~/.config/ai holds the launcher configuration (settings.env). ~/.ai/worklog is data for a skill that reports what was done on the previous day. user, answer to Q2
  • The ai image has no tzdata and no /etc/localtime. By default date shows UTC. docker run ai:latest dpkg -s tzdata; ls /usr/share/zoneinfo
  • The host runs Docker Desktop (linuxkit kernel, arm64). uname -a in the container

TZ=CET-1CEST,M3.5.0,M10.5.0/3 in the image

  • date: 12:12:20 CET, correct. TZ=Europe/Warsaw without tzdata gives UTC named "Europe". docker run ai:latest date
  • Node: GMT+0100 (Central European Standard Time), and Intl guesses Europe/Brussels. node -e
  • Python: +01:00, correct. python3 -c
  • Java: +01:00[GMT+01:00], a fixed offset without the daylight saving switch. jshell, Temurin 25
  • git: commit timestamps +0100. git log --format=%ad

Out of scope

  • The worklog format and content, and the skill that writes and reads it.
  • The dashboard container: the browser renders its times in the host time zone.

Decision log

Where should the container get its time zone from?

No image change and no rebuild. Java gets a fixed GMT+01:00 offset instead of a zone, and historical dates (before the current rules) may get a wrong offset. Add tzdata to the Dockerfile and pass TZ=Europe/Warsaw from readlink /etc/localtime. Correct everywhere, including Java and historical dates, but needs an image rebuild and different zone detection on macOS and Linux. The most robust, but two code paths in the launcher to maintain.

Containers are short-lived and the worklog needs the current local time, which date, Python, Node and git get right. The Java fixed offset and historical dates do not matter for it, so the patch stays as decided in D44 and D45 without touching the image.

Where should the worklog live on the host?

Matches decision D43 and the tool that already writes there. Departs from the XDG direction of c8aeb3a. Consistent with ~/.config/ai/settings.env, but D43 and the host-side tool would have to change.

This is something else - ~/.config/ai really is configuration. ~/.ai/worklog only concerns the skill that, based on the worklog generated from ai, tells what I did on the previous day.

c8aeb3a moved configuration to XDG. The worklog is skill data, not configuration, so it does not follow that move and stays where D43 put it.

Should the README describe the worklog mount and the time zone?

The README already describes every host directory it mounts, so the new one belongs there too. Less text, but hidden launcher behaviour.

Every other host mount is documented in the README, and the time zone changes what date shows in the container.
